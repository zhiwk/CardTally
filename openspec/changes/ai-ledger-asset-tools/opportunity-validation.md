状态：案头调研和产品范围决策已完成；案头资料不是外部用户需求证据。产品所有者已确认完整账本/资产工具范围，实施约束见 `docs/requirements/decisions/2026-09-26-ai-financial-tools.md`。

日期：2026-09-26

## 问题假设（尚未验证）

使用多个本地账本或共享资产组的 CardTally 用户，可能希望通过自然语言快速查询、整理账本或资产，而不必逐层进入管理页面。当前仓库事实只证明应用已有 MiniMax BYOK 持久化文本聊天、SQLite 本地核算和账本/资产管理能力；没有证据证明用户经常遇到此类操作摩擦，或愿意把财务字段发送给模型 Provider。

可能受益的场景是“找到并辨认同名资产/账本”“检查资产属于哪个共享组”“发起一个明确的名称修改”。高影响场景如余额校准、永久删除和账本级联删除，不能由“想省步骤”推导出用户授权。

## 当前产品与业务边界

- `README.md` 描述的是本地 SQLite 记账和可选 MiniMax BYOK 文本聊天；没有 AI 财务实体查询或写入能力。
- 已确认决策 `2026-08-12-light-ux-redesign.md` 第 4 节明确禁止从旧方向推定 AI 可操作财务数据或启用审计日志；新的写操作必须另有明确决策。
- 账本资产组规则见 `2026-09-11-ledger-asset-groups.md`。现有删除和共享引用属于财务业务规则，AI 不得绕开。
- 当前实现具有实质约束：`AssetWriteRepository` 的管理操作按当前账本作用域执行；资产删除检查目前按名称引用；`LedgerWriteRepository.deleteLedgers` 会删除关联记录并处理资产池引用；账本详情更新受当前账本限制。OpenSpec 中“任意账本/资产 CRUD、按稳定 ID 判定引用、级联影响预览”尚无共同领域服务支撑，不能仅接入工具调用就视为符合现状。

## 初步判断

- 可能差异化：本地记账应用中的可选 BYOK 助手，以受限请求读取本地实体，并将结构化建议交由原生界面预览；它不需要云端账本服务。
- 尚未证实的核心价值：比现有页面操作究竟减少了多少摩擦，以及减少的摩擦是否值得引入 Provider 数据披露、模型歧义和误操作风险。
- OpenSpec 范围较宽（Provider 替换 + 账本及资产全 CRUD + 余额校准 + 删除级联 + 审计数据库）；产品所有者已选择完整范围，新的有约束力限制见 `2026-09-26-ai-financial-tools.md`。
- 首发实现仍应分阶段交付：先完成逐请求外发授权、领域规则服务、精确预览/审计底座，再逐类开放查询和写操作；这是工程顺序，不缩减已确认的最终产品范围。

## 最小验证范围与停止条件

1. 由产品所有者提供至少一个本人实际遇到、可复现的账本/资产管理场景，并说明当前操作路径和具体摩擦；不得把推测写成用户事实。
2. 用合成数据对比现有页面流程与只读查询/预览原型，检查同名实体消歧、共享组归属理解、字段披露理解和用户是否信任确认卡片；不得发送真实财务数据或真实 API Key。
3. 只有当一个重复且具体的问题成立、用户理解模型 Provider 会收到哪些字段，且本地业务规则能够无旁路复用时，才决定是否实施；第一阶段应先做只读或可撤销的小范围写入。
4. 若没有反复发生的用户问题、用户不接受所需字段外发，或无法为共享关系与级联删除给出可验证预览，则停止该写入范围或退回纯聊天，不继续扩张 Provider/数据库迁移。

## 已由产品所有者确认的范围

- 允许未来 AI 账本与资产完整 CRUD；不包括直接账单、分类、转账或预算工具。
- 允许余额校准但须双重确认；允许账本删除级联但须精确影响预览和二次确认。
- 财务工具默认关闭，每次外发财务字段前逐请求授权；操作审计本地保存并可由用户清除。

## 仍需实施时解决的工程细节

- 把名称历史引用、来源/转入资产稳定 ID、撤销窗口及永久删除保护统一为可靠检查；不满足时拒绝删除。
- 删除账本的共享资产迁移、当前账本回退和级联计数必须来自同一事务语义。
- 由可复用领域服务承担跨账本授权范围，保留页面当前账本编辑限制。
