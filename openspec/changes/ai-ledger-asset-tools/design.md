## Context

当前 Android 客户端使用 Kotlin、Fragment、XML、Material Components、手写 SQLite `DatabaseHelper` 和 MiniMax 专用 Chat Completions 流式客户端。聊天会话已本地持久化，但消息结构主要面向 `role/content`，尚不能可靠表达跨 Provider 的工具调用、Provider 私有续接字段、待确认操作和执行结果。目标状态允许使用多种大模型 Provider，并以 DeepSeek 作为默认 Provider。

账本与资产并非两个孤立表：资产通过稳定资产 ID 和资产组被多个账本共享；主账本、资产组根、引用关系、归档状态及已使用资产删除条件都有现行业务规则。AI 只能通过同一领域服务复用这些规则，不能拥有旁路数据库权限。

## Goals / Non-Goals

### Goals

- 保持普通聊天和历史会话能力。
- 支持可扩展的大模型 Provider，默认使用 DeepSeek，并保留用户已有的有效 Provider 配置。
- 让 AI 能按稳定 ID 查询、新建、修改和删除任意账本及资产。
- 在数据出设备、写入执行和不可逆删除前给用户可理解、可验证的控制点。
- 防止陈旧预览、重复提交、模型重试或流式重连导致重复写入。
- 让每次写入都可追溯，并能区分模型建议、用户确认、成功、拒绝和失败。

### Non-Goals

- 不操作账单记录、分类、转账、预算或统计结果。
- 不调整资产组关系，不执行账本合并或资产合并。
- 不让模型执行 SQL、任意代码、系统命令或未注册工具。
- 不提供无人值守、自主循环执行或后台定时财务操作。
- 不把本地优先改造成云端记账，也不声称具备财务顾问或审计合规能力。

## Decisions

### 1. 使用 Provider adapter 和统一工具协议

新增 `AiProviderClient` 接口，将流式文本、结构化工具调用、工具结果和取消语义转换为客户端统一模型。DeepSeek 作为默认 adapter；其他 Provider 通过显式 adapter 接入，OpenAI-compatible 端点可复用兼容 adapter，但只有通过能力探测和契约测试后才能启用财务工具。现有 MiniMax 配置作为历史 Provider 配置迁移，不得静默改写为 DeepSeek。

工具协调器负责 schema 校验、循环上限和请求关联；账本/资产服务负责业务校验及事务。模型只能返回已注册工具名和 JSON 参数。未知工具、未知字段、类型不符、越界金额或不存在 ID MUST 被拒绝，且拒绝结果可作为工具错误返回模型，不产生数据库写入。

统一能力描述至少包含 `streaming`、`structuredTools`、`parallelToolCalls`、`thinkingContinuation` 和协议版本。某 Provider 仅支持聊天时仍可被选用，但财务工具入口 MUST 标记不可用。Provider 名称、base URL、模型 ID、协议类型和 API Key 彼此绑定；切换 Provider 或模型时，未确认操作立即失效，历史可见消息保留。

建议工具集合：

| 类型 | 工具 | 说明 |
|---|---|---|
| 读 | `list_ledgers` / `get_ledger` | 列出或按 `ledger_id` 获取账本及必要的资产组摘要 |
| 读 | `list_assets` / `get_asset` | 按全部、账本或资产组范围查询，使用 `asset_id` 消除同名歧义 |
| 写 | `create_ledger` / `update_ledger` / `delete_ledger` | 新建、修改、删除账本；创建时必须明确独立组或复用的资产组 |
| 写 | `create_asset` / `update_asset` | 在明确资产组中创建资产，或修改名称、类型、分类、图标、计入总额、置顶及余额 |
| 写 | `archive_asset` / `restore_asset` / `delete_asset` | 归档、恢复或在满足现有条件时永久删除资产 |

工具参数只接受稳定 ID，不以显示名称作为最终写入目标。名称查询有多条匹配时，AI MUST 向用户消歧。

### 2. 查询可自动执行，写入在 AI 聊天页确认

财务工具总开关默认关闭。打开时展示数据会发送给当前选定 Provider 的范围。开关打开后，符合当前用户请求的只读工具可自动执行；写工具只生成 `PendingOperation`，其中包含规范化参数、影响摘要、目标快照、Provider/模型标识、过期时间和一次性操作 ID。

`AgentChatAdapter` 根据已校验的 `PendingOperation` 在 AI 聊天消息流中渲染原生操作卡片，而不是渲染模型返回的 HTML、Markdown 或伪按钮。卡片至少显示操作类型、目标、变更前后、影响范围、过期状态，以及“确认执行”“取消”按钮。普通写入点击一次确认；余额校准、账本级联删除和资产永久删除在同一卡片切换到“再次确认”状态。点击后按钮立即禁用并展示执行状态，最终替换为成功、取消、过期或失败结果。聊天文本、模型输出、键盘回车或重新发送均不能代替按钮确认。取消、会话切换、Provider/模型切换或操作过期后 MUST 失效。

### 3. 预览与执行之间采用乐观并发校验

预览记录目标实体及相关引用的版本或规范化快照指纹。执行时在单个 SQLite 事务内重新读取并比较；目标不存在、内容已变化、当前业务规则不再允许或操作 ID 已使用时 MUST 拒绝执行并要求重新预览。成功写入和审计完成属于同一事务；工具重试使用相同幂等键，不得重复创建或删除。

### 4. 共享资产按所有者根操作，展示全局影响

AI 可定位任意资产，不需要切换当前账本。共享资产写入由其资产组所有者根执行，并继续遵守现有权限与保护规则。预览 MUST 列出受影响的全部引用账本数量和名称摘要；修改共享资产余额或属性会对引用它的账本同时生效。AI 不得复制资产来规避权限。

### 5. 删除沿用现有规则并提供影响计数

主账本、受保护的资产组根或其他现行业务规则禁止删除的账本 MUST 被拒绝。账本删除预览 MUST 明确显示将删除或重新归属的账单记录数、资产引用变化、当前账本回退目标和是否可恢复。资产永久删除仅允许已归档且从未被记录引用的资产；否则只能归档。规范不新增通用撤销，因此永久操作不得承诺可恢复。

### 6. 最小化上下文与本地审计

客户端不在每轮对话预先上传全部财务数据。仅在模型发起与用户请求一致的读取工具后返回必要字段，并限制分页、条数及工具循环次数。资产或账本名称一律作为数据引用，不作为系统指令；来自数据库的文本不得改变工具权限或确认规则。

本地审计至少保存：操作 ID、会话 ID、Provider/模型标识、工具调用 ID、工具名、规范化参数/影响摘要、目标快照指纹、用户决策、执行状态、错误类别和时间。审计不保存 API Key、Authorization 头或模型内部推理。聊天层持久化使用统一的可见消息、工具调用、调用 ID 和最小工具结果；Provider 为继续当前工具链所要求的私有续接字段只能保存在隔离的 Provider 扩展字段中，不得展示、写入审计或传给其他 Provider。若 adapter 无法安全维持所选模型的续接要求，该模型只能纯聊天，不能启用财务工具。

### 7. 明确降级与有限循环

只有在所选 Provider/模型能力声明支持结构化工具且接口返回合法调用时才进入工具流程。DeepSeek adapter MUST 正确处理其工具调用 ID、工具结果配对及所选模式要求的续接字段；其他 adapter 通过各自协议做等价转换。缺少能力、响应不可解析、流式中断或达到循环上限时，保留普通聊天并向用户说明本次没有执行财务操作。单个用户回合最多允许一个待确认写操作；后续写操作必须等待前一个结束。

### 8. 默认 Provider 与配置迁移

新安装、无有效历史 AI 配置或用户主动恢复默认时，Provider 默认选择 DeepSeek，模型 ID 由集中式 Provider catalog 提供一个当前受支持且具备结构化工具能力的 DeepSeek 默认值，不在 UI 多处硬编码。用户可修改 Provider、模型、base URL 和 API Key；自定义端点必须选择明确协议并通过最小能力探测。

升级时若存在完整 MiniMax 配置，应用将其迁移为 `provider=minimax` 的历史配置并继续使用，除非用户主动选择 DeepSeek；不完整的旧配置可保留但不得被当作可用财务 Provider。不同 Provider 的 API Key MUST 分开存储，切换时不得把一个 Provider 的密钥发送给另一个端点。

## Risks / Trade-offs

- 财务上下文离开设备：通过默认关闭、启用披露、按需查询和最小字段降低风险，但无法消除第三方模型处理数据的事实。
- 模型选错实体：稳定 ID、同名消歧和确定性预览能降低风险；用户仍需要认真确认。
- 直接余额修改破坏账实解释：本规范将其定义为高风险“余额校准”并审计，但不会自动生成账单；如产品希望所有余额变化都有流水，应在实施前删除该能力。
- 删除可能触发现有级联行为：必须以当前 `DatabaseHelper` 与业务决策为准生成实际影响，不允许模型自行推断。
- 协议历史会扩大本地聊天数据：迁移和清理策略需覆盖新字段；审计保留期需要产品后续确定，默认跟随本地数据库生命周期且不自动上传。
- “OpenAI-compatible”不等于所有端点行为完全一致：必须通过 adapter 能力探测和契约测试决定是否开放工具，不能只凭接口路径相同就允许写操作。

## Migration Plan

1. 先更新有约束力的业务决策和 `AGENTS.md` 中 AI 能力边界，再进入代码实施。
2. 引入 Provider 抽象和 DeepSeek 默认配置，迁移但不覆盖有效 MiniMax 历史配置；以非破坏性迁移增加协议消息、待确认操作幂等状态和审计表。
3. 先使用 DeepSeek/兼容 Provider 的假 adapter 实现只读工具和协议测试，再实现普通写入、共享资产影响和高风险删除。
4. 通过隔离 `verification` 变体覆盖会重置数据库的设备测试；日常变体仅做不破坏真实数据的人工验证。
5. 若迁移或工具能力探测失败，保持原聊天功能并隐藏财务工具入口。

## Open Questions

- 是否最终允许 AI 直接校准余额，还是所有余额变化必须由账单/转账产生？本规范暂按允许但二次确认处理。
- 本地审计是否需要面向用户的独立查看与导出页面？本规范要求聊天内可见执行卡片和持久化审计，但不要求独立审计中心。
- 账本删除是否应在 AI 场景进一步收紧为仅允许空账本？本规范暂沿用现有规则并展示实际级联影响。
