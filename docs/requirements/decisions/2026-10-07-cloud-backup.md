# WebDAV / S3 加密云备份与恢复

## 用户确认的范围

云备份与恢复，不做多设备实时同步。WebDAV 与 S3 同时提供；手动备份加可选每日自动备份，新配置默认勾选本机加密保存备份密码与每日自动备份，确认保存有效配置后才加密存储并安排任务；已有配置保留原选择（此项取代早期自动默认关闭规则）。自动备份仅 Wi-Fi，不提供限速。自动历史保留数量可设置，默认 15 份，范围 1–365；手动备份不自动清理。完整备份补齐自选背景图库与选择状态。

## 实现与安全边界

- 「我的 → 云备份」独立二级页，配置连接、测试读写、保存、立即备份、列举、预检恢复、确认合并与确认删除。两种连接配置分别保存，当前启用一种作为自动目标；断开清除所有本机云连接及保存的密码，保留远端文件。
- 只支持 HTTPS，系统证书验证且不自动跟随重定向。WebDAV 使用 Basic / 应用专用密码、PROPFIND Depth 1、MKCOL、GET、PUT、MOVE、DELETE；S3 使用 SigV4、ListObjectsV2 分页及 GET/PUT/DELETE，支持路径式/虚拟主机式及 Session Token。需要服务支持防覆盖创建：WebDAV 将随机临时文件 MOVE 到目标并使用 Overwrite: F，S3 使用 If-None-Match 条件 PUT；连接测试验证第二次创建被拒绝且原文件内容不变，不遵守即停止。此项替代早期两种服务均只使用条件 PUT 的实现，以保持防覆盖约束并支持标准 DAV 语义；不宣称所有服务商兼容。
- 备份仍包含财务数据、账单照片、设置、AI 聊天和已保存的 AI API Key；页面和保存确认说明范围。连接凭据、云任务状态、设备命名空间与云备份密码不进入备份。
- 云配置文件位于 noBackupFilesDir，Android Keystore AES-GCM 保护。备份密码至少 8 位；手动可不保存密码，自动要求用户勾选保存。本机密码和连接配置不是云端找回途径，忘记备份密码不能恢复。更换已建立空间的密码需使用新目录，不原地重新加密历史。
- 云目录按 dev/release 分隔。vault.json 保存随机盐及密码验证值；PBKDF2-HMAC-SHA1 200000 次派生 256 位密钥，文件压缩后 AES-GCM 加密并绑定格式 AAD。随机 nonce 独立于文件内容，文件名使用密钥 HMAC 的原始内容标识，不暴露明文照片哈希。
- 每次保存完整数据快照，照片和背景分文件增量上传，同一安装实例的历史共享相同内容文件。为避免跨设备清理竞争，设备命名空间独立，不跨设备去重；备份来源映射仍保留既有跨设备合并规则。
- 初次或新增对象上传后读回并验证；后续复用已完成加密清单中的已验证对象，正常备份不会下载旧图片。自动内容指纹相同则跳过新快照，仍可重试历史清理。重试可复用已完整上传的文件；无引用的中断对象可修复。不实现单文件分段续传或上传限速。
- 最后发布唯一命名的加密 snapshot 清单作为完成标记，未完成对象不出现在备份历史。清单也压缩后加密，清理复用本次已验证清单，减少重复下载。列表显示时间、自动/手动、随机设备标识片段和当前对象大小总计（不含服务端回收站、S3 非当前版本）；传输显示新增上传估算及实际上传/下载字节数。新对象读回验证会增加下载流量，不能把上传估算当全部流量。
- 使用 WorkManager 日周期和网络 CONNECTED 条件，再在开始与每次网络读写检查实际 Wi-Fi transport 和有效连接，避免把“不限流量”误当 Wi-Fi。离开 Wi-Fi 后中断并退避重试，不承诺固定时间；错误凭据/密码需要用户修正。长任务仍受 Android 后台调度限制，首次大量数据建议手动前台备份。
- 新备份确认成功后，仅清理当前设备、当前渠道超过保留数量的自动清单；之后只删除同设备已无任何保留清单引用的对象。手动清单及其他设备保留。若清理失败，已完成备份有效，页面报告清理未完成。删除其他设备清单不自动清理其图片，防止与该设备上传竞争。
- 恢复下载、验证并重建私有 ZIP，先调用原有回滚式预检；确认后使用同一个已验证本机缓存合并，不重复下载图片。已有条目和资产余额冲突沿用原决策，删除不传播。正式数据库合并开始后不提供取消按钮；取消下载不会发起合并。
- 本机缓存可能暂存完整 ZIP、压缩附件及已验证恢复包，需要足够空间。每个操作结束清理工作目录，恢复缓存由页面 ViewModel 清理；进程被终止留下的超过一天缓存在下次操作时清理。清单、文件和累计展开大小均有上限，沿用财务备份的总体限制。

## 备份格式兼容

本地完整 ZIP 版本从 2 扩展为 3，新增 wallpapers 条目和 selectedWallpaper；加密容器仍沿用原 CTB3。本版本仍接受 v2 ZIP 及旧 JSON，旧应用不能恢复新 v3 格式。默认三张图片只保存选择 ID，不复制打包资源。自选图库按内容合并，同内容恢复不重复创建，已有图库和选择不覆盖；未设置主题且无自选图的初始状态采用备份选择。数据库和系统文件不能组成单一事务，数据库提交后若图库写入失败应报告失败，重试利用既有身份映射避免重复账单。

## 验证状态

仅完成实现与静态检查。添加文件加密/篡改/去重标识、历史保留隔离及 AWS 官方 SigV4 样例的 JVM 用例，未执行。没有构建、单元测试、设备测试、安装或真实 WebDAV/S3 连接验证授权。本轮不读取用户云凭据、不接触远端空间、不推送 GitHub。

后续经用户明确要求验证时，先执行相关 Debug 单测；数据库、背景恢复和任务隔离验证只在 verification 变体；再使用用户指定服务测试首次备份、无变化跳过、新增图片增量、Wi-Fi 中断、恢复不重复下载、错误密码、配置切换与 15 份历史清理。

WebDAV 随机临时上传文件在 MOVE 完成时由服务端移除，失败/取消时尽力删除；进程终止或断网可能留下临时文件，不作为有效备份，不批量删除其他操作的暂存文件。错误提示仅显示操作方法和 HTTP 状态，不包含 URL、凭据或响应正文。

协议参考：[AWS SigV4](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/sig-v4-header-based-auth.html)、[WebDAV](https://www.rfc-editor.org/info/rfc4918/)、[Android 网络约束](https://developer.android.com/reference/androidx/work/NetworkType)。

## 坚果云目标已存在响应兼容

用户真机反馈 MOVE HTTP 409。KeePass2Android 项目原始问题及后续修复记录指出，坚果云向已存在目标执行移动会返回 409。CardTally 不采用该项目针对替换文件的「删除目标后移动」做法：当前只做禁止覆盖创建，仅在连接主机严格为 dav.jianguoyun.com、MOVE 返回 409 且对确切目标 HEAD 成功时，视为目标已存在并返回未创建。连接测试仍读回原文件核对哈希不变；目标不存在或探测失败不视为防覆盖成功，保留具体错误。暂存文件按原规则清理，不删除原目标；其他服务与 S3 行为不变。

依据：[KeePass2Android 原始问题与服务兼容记录](https://github.com/PhilippC/keepass2android/issues/3010)。截图尚不能证明 409 是首次移动还是第二次测试；该兼容分支需真实服务再次测试，未读取用户凭据或执行云端请求。
