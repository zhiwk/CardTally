# 资产初始余额与手动调整流水

2026-11-01 用户确认：资产详情需要两类条目，初始化为初始余额条目，修改更新余额为调整余额条目；按沟通方案执行。

## 业务规则

- 新建资产生成一条「初始余额」，记录创建时的余额，包含零余额与负余额。已有资产不推算、不补造过去的初始金额、日期或调整历史。
- 用户手动保存不同的余额时追加「调整余额」，保留修改前、修改后的余额和实际发生日期，金额展示为新余额减旧余额的有符号差额。500 改为 600 展示 +100；600 改为 400 展示 -200。每次调整独立保留，不覆盖之前的条目。
- 金额不变的名称、图标、类型、计入总资产等编辑不生成调整；收支/转账账单的新增、编辑、删除及撤销继续由原账单流水解释，不额外生成手动调整条目。
- 资产和对应余额条目必须在同一 SQLite 事务中提交，失败一起回滚。差额基于事务内读取的已保存余额，不读取可能已被编辑器修改的对象旧值；金额以整数分保存，溢出不得截断。
- 初始与调整条目属于资产，不是账单，不绑定分类、不计入收入/支出、分类统计或流入/流出；仅在资产详情中与正常账单按日期合并展示。普通账单入口、统计、日历、搜索和 AI 账单工具不将其作为账单查询或修改。
- 两类条目暂为只读，不复用账单编辑/删除入口；用户需要再次修改余额时通过原资产编辑入口操作。它们不扩大共享资产的管理权限，原所有者限制继续有效。
- 共享资产按同一资产 ID 共用余额历史。归档保留条目；原删除保护仍生效，资产被允许删除后级联清理其余额条目。账本合并/资产所有权迁移保持资产 ID 和条目不变；复制资产使用新 ID，只记录复制时余额为新资产的初始余额，不复制源资产的过去调整。

## 数据与备份

- SQLite v44 增加独立 `asset_balance_events` 表，保存资产 ID、种类、日期、时间戳及变动前后整数余额；日常升级只建空表/索引，既有财务数据不重写。verification 仍沿用隔离重置策略。
- 详情的正常账单与余额条目通过同一 SQL 联合查询和稳定游标分页，不把双方的第一页拼接当作完整历史。同日余额条目按时间与 ID 倒序，正常账单保留原排序；不假定没有时间字段的历史账单具备精确时分秒。
- 完整与云备份包含这些财务条目。ZIP 清单升级为 v4，v2/v3 缺失此表时按没有历史处理，v4 缺表必须失败，不能静默丢失历史。旧应用不能恢复 v4。
- 恢复按原来源安装实例及条目 ID 去重，重映射资产 ID；预检回滚，重复导入不重复插入，更不重放差额。资产余额继续按原快照/冲突确认规则恢复，不把恢复本身伪装成一次手动调整。
- 旧 JSON 继续原有兼容合并方式，新增余额表可随 JSON 导出/导入，不改变其缺少完整附件内容和采用内容去重的旧格式边界。

## 本轮范围与验证边界

只增加这两类资产流水，不照搬参考截图中的还款、月份筛选或整页样式。条目沿用现有主题与列表布局，金额使用中性色而非收支语义色，显示日期及修改前后余额，并保留普通账单的账本归属和详情入口。
