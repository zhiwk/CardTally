# 完整备份与合并恢复的数据边界

> 2026-09-27 用户确认：设置项、账单照片和 AI 聊天记录都包含；恢复时与本机现有数据合并。

## 范围

- 手动导出的完整备份包含全部账本、共享账本和共享资产关系、分类、资产、账单记录、重复记账任务、AI 会话与消息，以及账单引用的照片文件。
- 包含应用持久化设置，保留 SharedPreferences 值的布尔、整数、长整数、浮点、字符串和字符串集合类型；包含用户保存的 MiniMax API Key。
- 删除记录后的短时撤销缓存、验证环境重置标记和备份内部来源映射属于运行状态，不作为可恢复的账本或设置。
- 手动备份在本地生成，由用户选择保存位置；新导出格式为密码保护文件，包含财务数据、照片、聊天内容和 API Key。密码不写入备份文件；忘记密码无法恢复。应用不主动上传手动备份。

## 合并规则

- 恢复时保留本机已有的账本和条目；导入条目创建新的本机 ID，再重建分类父子关系、记录引用、共享资产关系和重复记账转入资产引用。
- 每个来源安装实例与来源条目 ID 组成导入身份。导出再次携带已经合并过的来源身份，避免 A → B → A 往返时重复插入；重复导入同一备份时，仍存在的已导入条目不重复创建。两条金额、日期和文字完全相同但 ID 不同的真实账单必须都保留。
- 同名账本、分类或资产来自不同来源时仍可并存，避免按名称误合并或篡改已有余额。设置按键合并：完全空白的初始安装采用备份设置；已有数据的设备保留本机同名设置，只补入缺失键。写入备份中的账本、资产、分类或 AI 会话 ID 设置时映射到新 ID。
- 已导入账单的本机附件若仍可读取，重复合并不改动；若账单仍在但关联照片文件丢失，可从备份重建该账单的照片附件。
- 新导出格式为加密文件，内部是包含 JSON 清单与账单照片的 ZIP；先验证完整性再合并。此前未加密的 ZIP 和 v1 JSON 仍可导入，但 v1 JSON 只有 URI 而没有照片内容，且使用旧合并规则，不能作为完整备份。
- 对完全符合初始种子数据、没有其他条目的新安装，导入时在事务内移除自动生成的默认账本和分类，避免与备份重复；已修改过的默认数据保留。
- 增量合并使用上次导入的资产余额快照：本机余额未变化时可采用新备份余额；两边余额都已变化时默认取消合并。用户可以明确选择采用备份中的冲突余额，再查看预检并确认正式合并。现有条目与备份字段不同但不涉及余额时保留本机版本，完成后报告差异数量；删除不随合并传播。
- 新 ZIP 格式在正式合并前运行一次数据库回滚式预检，展示预计新增、跳过及本机差异数量；用户确认后重新读取文件并执行正式合并。预检与正式合并之间若本机数据变化，实际结果可能不同，正式合并会再次校验余额冲突。
- 导出或恢复遇到不可读取的账单照片、缺失引用、缺失 ZIP 条目或不支持的格式时应失败，不得报告完整成功。

## 交付边界

当前实现入口为「我的 → 导出完整备份 / 合并备份」。新导出使用 PBKDF2 派生密钥、AES-CTR 加密及 HMAC-SHA256 完整性校验；旧明文备份仍可导入。不宣称任意跨版本兼容。系统 Auto Backup 已在 Manifest 与规则中关闭云端提取和设备传输；恢复后的语言切换等全局 UI 状态可能需要重新进入应用才能反映。

当前实现对清单限制为 128 MiB、单张照片 50 MiB、照片合计 1 GiB、加密文件 1.2 GiB。导入加密文件时会暂存一份于应用缓存中以先完成完整性验证，因此需要额外可用空间。超过限制会报错，不会把截断的文件标记为完整备份；大账本仍需要在运行验证中确认实际可用规模。

数据库条目的合并使用事务；设置写入无法与 SQLite 和 SharedPreferences 组成单一事务。正式合并会在同一 SQLite 事务中保存待应用的设置及 ID 映射，再提交账本数据；如果设置写入失败，待应用记录会保留。之后再次确认合并时先重放该记录，再继续导入，来源映射保证已导入条目不会重复插入。回滚式预检保持只读，不会重放或清除待应用记录。设置完成写入后才清除待应用记录；若在这两步间退出，重放会幂等执行。

后续运行验证应在隔离的 verification 变体中覆盖：相同内容但 ID 不同的两条账单、同一备份重复导入、A → B → A 来源身份往返、已有本机数据保留、照片跨安装包 URI 重建与本机照片丢失后的修复、重复记账双资产引用、AI 会话消息，以及 Int/Long/Float/StringSet 设置值的读取。当前源码改动尚未经过构建或运行验证。
