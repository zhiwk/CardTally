# 轻量卡片体验重设计决策

> 决策日期：2026-08-12
> 生效日期：2026-08-12
> 状态：已确认，待实施
> 适用范围：CardTally 后续产品、视觉、主题和 AI 概览实现

## 1. 优先级与实施状态

本决策自生效日期起，取代旧的三主题方向和“静奢理财日记”视觉方向，作为后续重设计工作的产品和视觉约束。

当前 Kotlin、XML、资源和 Gradle 配置仍是运行时事实。本决策不声称主题迁移、视觉重设计或 AI 概览已完成，也不改变已实施的本地优先记账、叶子分类绑定、扁平分类统计和既有余额核算规则。实施完成前，当前源码所呈现的浅色、深色和跟随系统主题仍是现状，不应被本决策误述为已经移除。

本决策优先于以下相冲突的当前方向：

* `README.md` 中的浅色、深色和跟随系统主题说明。
* `docs/collaboration/current-snapshot.md` 中的三主题运行时快照。
* `docs/collaboration/task-entrypoints.md` 中以三主题为前提的主题任务说明。
* `docs/design/guidelines/` 中的“静奢理财日记”身份与相关视觉指导。
* `docs/requirements/decisions/business_rules.md` 第 3 节中 Agent 可直接执行业务操作并生成审计日志的方向，仅限本决策第 4 节所作收窄。

历史计划和历史设计材料保留原文，作为当时意图或参考，而非当前实施完成的证明。

## 2. 产品、主题与视觉方向

后续运行时只保留浅色外观。深色和跟随系统不再是用户可选项，也不得造成夜间模式下的视觉变化。现有已存主题值应在实施时归一为浅色，同时不得清除或重置无关偏好。

新的界面语言是黑、白、灰为主的描边卡片系统：

* 页面与容器以白色或浅灰色表面、细灰色描边和克制层级组织。
* 卡片用于有意义的分组和层级，不得将每个标签、行或控件都包成嵌套卡片。
* 仅可使用浅淡、低饱和度的语义色作为状态提示，例如收入、支出、警示或选中状态。它们不是品牌主色，也不能替代文字、图标或其他非颜色语义。
* 不使用高饱和度调色板、装饰性渐变或旧“静奢理财日记”身份语言作为现行设计合同。

## 3. AI 概览的触发方式与数据边界

AI 概览是用户明确触发的文本生成，不是记账自动化。只有用户发起生成操作时，才允许向 MiniMax 发出一次概览请求。不得自动请求、后台刷新或根据数据变化自行发送请求。

概览请求的财务数据允许列表仅包含以下字段：

1. 所选期间标签。
2. 汇总收入金额。
3. 汇总支出金额。
4. 汇总余额金额。
5. 最多五个扁平叶子分类的分类名称和汇总金额对。

除上述字段外，概览请求禁止包含以下内容：

* 单条记录或任何原始记录行。
* 备注、描述或其他自由文本。
* 资产、资产名称、资产余额或资产关联信息。
* 分类路径、父分类或非叶子分类结构。
* 本地或远程路径。
* API Key、模型凭据、请求认证信息或其他密钥。
* Agent 聊天历史、会话内容或聊天消息。
* 记录、资产、分类、会话、用户或设备的任何标识符。

概览结果只是一段文本。后续实现可以在本地保存该文本及其聚合输入指纹和生成时间，但不得把结果写入 Agent 会话，也不得据此创建、修改、删除或恢复财务数据。

## 4. Agent 操作与审计日志边界

> 后续决策：AI 账本/资产工具已由 `2026-09-26-ai-financial-tools.md` 单独确认。当前代码仍未实现该能力；本节对当前运行时及 AI 概览的数据边界继续有效，未来账本/资产工具仅按新决策实施。

`business_rules.md` 第 3 节的 Agent 直接执行业务操作与完整审计日志方向，在本次重设计中不启用。该节不授权本次重设计新增 Agent 对记录、资产、分类或余额的创建、修改、删除、转账或其他记账操作。

本次重设计也不启用审计日志功能、审计日志模型、审计日志表或文件日志。现有 Agent 保持为可选的 BYOK 文本聊天能力。任何未来的 Agent 记账操作或审计日志提案都必须经过独立、明确的业务决策，不能从本决策或旧第 3 节推定获得授权。该独立决策现已由 `2026-09-26-ai-financial-tools.md` 对账本/资产范围作出；记录、分类、转账、预算和 AI 概览仍受本决策边界约束。

## 5. 资产关联的已接受债务

记录与资产仍采用当前按名称关联的行为。这是已接受的技术和产品债务，不应在本轮设计或文案中被描述为不可变的账户标识关联。

本决策不改变现有重命名和关联行为，也不引入资产 ID 迁移。涉及资产记录展示、归档、删除或重命名的后续工作必须保留既有保护规则，并如实呈现此限制。

## 6. 实施检查点

实施主题、视觉或 AI 概览前，相关变更必须同时满足本决策、现有源码事实和适用的业务规则。出现冲突时，应先记录差异，再以新的已确认决策明确调整范围，不得以旧计划或旧设计材料静默覆盖此合同。
