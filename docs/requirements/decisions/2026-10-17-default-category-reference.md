# 默认分类参考蜜蜂记账二级方案

用户要求参考 BeeCount（蜜蜂记账）的分类作为默认分类。本轮沿用卡片记账现有全局树形分类模式，采用其二级方案的常用名称、分组和顺序：支出22个父类/101个叶子，收入14个父类/40个叶子，总计177个节点。没有混入其另外一套一级分类模板；只有叶子可绑定账单。

## 参考与实现边界

- 上游参照固定提交 `54844964ed6ae88158b6a408894e3787b290dd33`：[分类结构](https://github.com/TNT-Likely/BeeCount/blob/54844964ed6ae88158b6a408894e3787b290dd33/lib/services/data/seed_service.dart)、[中文名称](https://github.com/TNT-Likely/BeeCount/blob/54844964ed6ae88158b6a408894e3787b290dd33/lib/l10n/app_zh.arb)。
- 上游当前是限制商业使用的自定义许可，不按 MIT/Apache 处理。本轮仅参考日常收支分类名称/分组，不引入或复制其 Flutter 初始化实现、图标素材、数据库结构、同步标识或代码依赖；由 CardTally Kotlin 独立初始化，使用已有 Tabler 向量图标。后续如需引入其软件实现/素材，应重新核对授权。
- 名称按目前 CardTally 初始化约定使用中文，不在本轮增加分类自动翻译/切换语言重命名逻辑。

## 生效范围与数据保护

- 新数据库首次初始化使用完整目录；现有分类为空时，仍沿用既有自动补建入口生成默认树。
- 2026-10-19 用户确认补充：已有用户也应看到全部默认分类。数据库升级到 v43 时，在升级事务中一次性追加缺少的默认分类；已有分类 ID、名称、图标、颜色、排序、历史账单、重复记账及默认选择不改动，不清库、不迁移账单引用。
- 新增父类排在对应收支类型的已有根分类之后；复用同类型、同名的现有父类时，缺少的默认叶子追加在其已有子类之后。同父类、同类型、同名且仍为叶子的节点复用，不重复插入。
- 同名现有叶子不能改成父类，否则原账单会违反只能绑定叶子的规则：保留原叶子，另在末尾新增同名默认父类。默认叶子名称若与现有非叶子子类冲突，同样保留原节点并新增可选默认叶子；允许这种保护旧引用所必需的同名展示，不重命名用户分类。
- 升级只执行一次，已完整初始化的默认树不重复新增；升级后用户删除、重命名分类不触发每次启动补齐。既有“全部分类为空时自动补建”行为保留。
- 分类仍全局共享，新建账本不复制/新增默认分类；类型0支出/1收入，父子均显式写入排序，账单仍绑定叶子ID。数据库版本由42升至43，不引入新架构。
- 分类目录是初始化与备份初始状态识别的共同事实源。恢复备份仅在既有严格空白条件下删除未经修改的新默认树；旧19节点默认树识别保留。名称、父路径、类型、图标、颜色、排序及行数必须完全匹配；修改过分类或存在业务数据时不清理。
