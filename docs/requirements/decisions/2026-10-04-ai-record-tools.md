依据：用户要求 AI 有能力对账单条目增删改查，并进一步明确中途查账和对齐信息不需要确认，只在最终修改条目时确认一次。该请求取代旧规则对账单工具的排除，并取代账单工具逐查询、逐请求和跨轮上下文授权弹窗；不授权其他财务对象的管理功能，账本/资产工具原决策不变。

## 范围与继续条件

为使用自然语言记账和查账的应用所有者提供可核对的建议，减少手工查找及表单录入。复用已有 SQLite 核算与原生确认；这轮不新增 Provider 平台、账本/资产管理、分类管理、预算操作、SQL、批量删除、图片理解或附件编辑。只有模型可形成有效建议、预览与实际余额效果一致且每次确认可追踪，才继续扩展；模型不支持工具调用或无法识别目标时明确失败或询问用户，不猜测写入。

## 用户流程

- API 配置中的“允许 AI 提出账单操作”默认关闭，开关即时保存；与 API URL/Key/模型保存独立。开关说明自动读取当前账本及向所配置服务/模型发送查询结果和本页上下文；开启后不再为每次查询、发送结果或上下文复用弹出确认。
- 开启后每条消息启用注册工具。服务与模型须支持 OpenAI 兼容的 Chat Completions `tools` / `tool_calls`；工具模式非流式，普通聊天仍流式。不把文本或代码块 JSON 当工具调用。
- 模型可自动查询账单、读取账户/叶子分类选项；信息缺失或目标不明确时通过聊天提问。允许单响应最多 8 个调用，各调用须为已注册工具、合法 JSON 对象参数且调用 ID 唯一；解析任一异常时整个响应不执行。多个查询在校验全部查询参数后串行执行，继续各自的账本作用域和审计，不增加用户确认。
- 多调用响应若含写入，不执行这些写入，也不直接生成预览：先完成其中的查询，再为每个写入返回明确的未执行结果，自动要求模型使用查询结果单独提出一条完整写入建议。只有独立的单条新增、修改或删除进入原生确认；不会擅自从多个写入中选择一条，不允许批量执行。写入已成功后返回不允许本轮追加写入的结果。
- 返回模型的历史保持一条包含所有调用的 assistant 消息，并按原调用顺序提供每个调用 ID 对应的 tool 结果；结果齐全后才继续请求，避免跨轮继承缺少结果的工具消息。单轮最多 12 次模型请求、12 个工具调用（包含未执行的写入建议），超过上限停止；单查询仍最多 20 条，其他数据范围不扩展。
- 最终写入直接打开原生预览，显示账本与目标编号、修改前后字段、余额变化、共享资产影响、删除附件数量及 5 分钟有效期。用户点击一次“确认执行”后执行，聊天里说“确认”不具有写入权限；原操作卡片保留查看入口。每轮最多成功写入一条，成功后的模型请求只提供只读工具，控制器也拒绝追加写入；其他条目需新请求，不允许一次确认批量写入。
- 查询使用现有游标查询接口的可选页长，最多返回 20 条并提供连续游标（其他页面默认页长保持不变），选项各最多 100 项且可用关键词缩小，不发送余额、附件或操作日志。最终写入预览仍说明结果接收服务/模型，无额外的发送结果确认。
- 下一条消息自动保留本页内存中的澄清及查询上下文。不同配置、账本、会话或退出页面后不复用。工具聊天消息本地标为 `local_only`，不自动混入普通聊天历史；用户自己输入的消息按其主动发送行为处理。
- 本机回执先显示并随本轮最终消息持久化，模型后续回复失败不重新执行已经完成的操作。模型纯文本回复不能证明本机写入成功。

## 领域保护

- 限定发起消息时的当前账本，并使用 `DatabaseHelper` 实例级作用域，不切换全局账本。修改或删除使用稳定账单 ID；账户及分类也必须使用当前有效 ID。
- 收支仅允许匹配类型的叶子分类；资产可不选择，新增可省略或传 `asset_id: null`，修改省略保留、null 清除，见 `2026-10-04-optional-record-assets.md`。选择资产时仍校验有效账户 ID；转账必须有不同的非空转出/转入账户。不能移动账单至其他账本，修改保留现有附件。
- 金额使用非负/正数元字符串、最多两位小数，转换为整数分并验证 Double 边界可精确往返；拒绝溢出。日期为有效的四位年份公历日期。
- 新增、更新和删除调用现有 `addRecord` / `updateRecord` / `deleteRecord`，余额及转账手续费对称规则保持不变。不得独立校准余额或更改资产元数据。
- 执行前再次生成快照并比较指纹；账单、相关账户余额/归属/状态、分类或共享影响变化则失效。会话、API 配置、工具开关、当前账本变化或离开页面均取消待确认操作。
- 操作 ID 单次消费；核对、账单写入及成功日志在同一 SQLite 事务中完成，不通过重复确认重放。失败或过期不会继续外发工具结果。

## 持久化与审计

SQLite v42 只新增 AI 聊天本地标志和审计表；日常数据不重置，本轮不新增迁移。审计包含操作/会话/账本 ID、服务来源与模型、工具、目标 ID、快照指纹、状态和时间；记录提出、确认、成功、失败、拒绝、停止和过期。只有原生写入确认记录确认时间，自动查询不伪造用户确认事件。原生确认时间先记录；操作身份消费、财务写入和成功终态在同一事务内提交，失败时事务回滚，并由控制器记录失败终态，确认事件不会随财务事务回滚而丢失。

API 配置页可查看最近 50 项并明确清除全部操作日志，清除不影响账单、余额或聊天。审计不记录 Key、认证头、推理、Provider 原始响应或查询结果正文。目前日志只留本机，不参与完整备份；工具开关及聊天 `local_only` 标志参与已有设置/聊天备份。未完成的旧确认不恢复为可执行操作，下次工具请求将其标为过期。

多调用响应中未执行的写入记为失败终态，不记录确认时间、原始参数或目标快照；独立重提后按新操作身份建立真实待确认预览。查询仍各自记录成功且无原生确认时间，不新增数据库迁移。
