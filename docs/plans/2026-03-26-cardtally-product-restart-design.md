# CardTally 产品重开设计文档

## 1. 文档目的

本文档用于确认 CardTally 以“新产品重开”的方式继续推进，而不是在现有版本上做局部修补。

这是一份高层产品与信息架构设计文档，用来明确产品定位、设计方向、首版范围与结构边界。

本文档不展开以下内容：

- 具体页面线框
- 页面内模块排布
- 详细交互流程
- 文案细节
- 动效规范
- 视觉 token 数值

上述内容将在后续 UX / UI 细化文档中继续定义。

## 2. 重开结论

CardTally 应按“产品重开”处理。

现有代码库仍然有价值，但它应被视为技术资产，而不是新产品的结构模板。它的价值主要体现在：

- 可复用的数据模型与业务逻辑
- 现有能力盘点的参考基线
- 后续迁移与重构时的实现基础

新版本不应被当前页面结构、旧的信息架构或既有视觉风格所束缚。

## 3. 产品定位

新版本 CardTally 的定位不是“纯记账工具”，而是“具备 Agent 协作能力的财务陪伴型产品”。

它应当给人的感受是：

- 私人的财务日记
- 安静、克制、精致的日常应用
- 明显以设计驱动的产品
- 有独立助手角色参与日常财务记录与陪伴
- 虽然强调审美，但仍然具备日常记账可用性

它不应当给人的感受是：

- 数据密集的仪表盘
- 冷冰冰的后台工具
- 只是把表格包了一层 UI 的工具壳
- 常见的模板化记账 App

## 4. 已确认的核心方向

当前已确认的方向如下：

- 产品类型：财务陪伴型
- Agent 角色：独立助手入口
- 设计优先级：设计驱动，美观优先
- 风格平衡：杂志感 + 实用平衡型
- 视觉气质：静奢理财日记
- 首页角色：陪伴首页
- 首版范围：轻首版

这意味着新产品要追求鲜明审美和高级感，但不能为了视觉表达牺牲掉高频使用场景的基本效率。

## 5. 设计意图

新版本体验应同时具备以下特征：

- 编辑感排版
- 克制的高级感
- 安静的情绪氛围
- 轻度陪伴感
- 足够清晰的日常使用价值

整体设计需要避开两个极端：

- 过度艺术化，导致产品不好用
- 过度工具化，导致产品失去记忆点与情绪价值

最终目标不是把个人财务做成“管理面板”，而是让它更像一件有秩序感、私密感、长期陪伴感的日常产品。

## 6. 体验原则

### 6.1 美感优先

视觉质量是一等要求。版式、留白、字体层级、界面节奏、材质层次都需要先传达出完成度与审美水准。

### 6.2 先情绪，再数据

产品不应以强压迫感的数据面板迎接用户。财务信息应以更平静、更有节奏的方式出现。

### 6.3 陪伴感大于控制感

产品气质应更接近“陪伴”和“记录”，而不是“管理”和“控制”。

### 6.4 高频动作必须直接

尽管整体是设计驱动，但像“看记录”“记一笔”这样的高频动作必须足够直接，不能因为视觉表达而变复杂。

### 6.5 克制胜过堆砌

高级感来自比例、层级、材质、留白与节奏，而不是来自复杂装饰和过量元素。

## 7. 首版范围

首版聚焦 6 个信息架构一级能力区域：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

这里的“一级”指信息架构层级，而不是预先限定 UI 必须为一个独立导航按钮。

其中，“记一笔”被定义为一级能力，但首版 UI 呈现方式已明确为首页与记录页中的 FAB 入口，而不是单独导航按钮。

本阶段不追求“大而全”，而是优先建立新产品的骨架、气质与主干路径。

## 8. 一级信息架构定义

### 8.1 首页

首页的职责是：

- 作为产品的情绪入口
- 提供平静、轻量的财务概览
- 承担“最近值得关注什么”的引导作用

首页不是统计中心，也不应退化为传统 dashboard。它应是新产品最能体现“陪伴感”和“连续性”的页面。

### 8.2 记录

记录页的职责是：

- 提供完整账目浏览入口
- 承担记录查找、回顾、管理
- 作为用户处理历史账务的操作页

记录页是功能型页面，应清晰、完整、可管理。

### 8.3 记一笔

“记一笔”的职责是：

- 提供最快的交易录入入口
- 在信息架构中保持一级能力地位
- 作为用户最关键的高频动作之一存在

“记一笔”是顶层能力，但不预设其最终 UI 必须作为单独导航按钮出现。

### 8.4 资产

资产页的职责是：

- 展示账户、余额与资产状态
- 提供超越单条记录的财务状态视角

资产页应呈现更完整的财务秩序感，但依然不能做成技术感太重的后台页。

### 8.5 Agent

Agent 的职责是：

- 作为独立助手角色存在
- 承接与用户的财务协作关系
- 提供提醒、总结、解释、建议与待处理事项
- 成为用户与系统之间的主动陪伴层

Agent 不是隐藏在页面里的小功能，而是新产品中的核心角色之一。

### 8.6 我的

“我的”页的职责是：

- 承载低频但必要的个人化能力
- 作为偏设置、偏偏好、偏账户管理的统一入口

首版中，“我的”可作为主题、分类相关入口、偏好设置及其它二级能力的容器。

## 9. 首页定义

首页已确定为“陪伴首页”。

它需要在以下几者之间取得平衡：

- 情绪氛围
- 连续使用感
- 轻量财务方向感

它不应变成：

- 图表堆砌的统计页
- 只有审美没有信息的封面页
- 快捷入口杂糅的功能板

首页应回答三个问题：

- 我现在的状态如何
- 最近有什么值得注意
- 我接下来可能要做什么

## 10. 视觉方向

视觉气质已确定为“静奢理财日记”。

关键词：

- 安静
- 高级
- 宽松
- 克制
- 私密
- 编辑感

可能体现为：

- 更慷慨的留白
- 更讲究的字体层级
- 柔和但明确的对比
- 多层界面材质而不是平铺功能块
- 低噪声配色
- 适度点缀，而非高饱和功能色主导

## 11. 本次重开明确不做什么

本次产品重开不以以下目标为优先：

- 兼容旧页面结构
- 首版一次性塞入全部功能
- 以最快开发速度替代产品气质建设
- 在本阶段定义全部 UX 细节

这份文档只负责定方向，不负责把所有细节一次性说完。

## 12. 本阶段输出物

本阶段应产出：

- 本高层产品重开设计文档
- 后续实施规划文档

后续阶段再分别补充：

- 详细 UX 文档
- 页面结构与线框
- 组件规范
- 视觉系统
- 语气与文案策略
- Agent 专项能力文档

## 13. 对实现的影响

从实现角度看，应默认以下判断成立：

- 页面结构会发生较大变化
- 大量布局会重建，而不是小修小补
- 样式资源需要系统化重构
- 部分旧页面会被合并、降级或移出首版范围
- Agent 相关结构需要新增，而不是从旧代码里直接平移

也就是说，现有工程主要用于复用能力，不用于约束新产品形态。

## 14. 暂缓处理的开放问题

以下内容在本文档中有意不展开：

- 导航细节
- 页面线框
- 首页模块构成
- “记一笔”的具体入口形态
- Agent 的详细工作流
- 视觉 token 具体数值
- 动效系统
- 内容策略与文案语气

这些都属于下一阶段的 UX / UI 细化工作。

## 15. 结论

CardTally 应以“设计驱动、具备 Agent 协作能力的财务陪伴型产品”重新开始。

首版先聚焦 6 个信息架构一级能力区域：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

产品应优先建立安静、高级、私密、可长期使用的体验基础，在此基础上再逐步补齐更细的 UX、Agent 协作细节与更完整的功能层。
