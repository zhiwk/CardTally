# CardTally 首版页面职责文档

## 1. 文档目的

本文档用于明确 CardTally 首版 6 个信息架构一级能力区域分别负责什么、不负责什么，以及它们之间的边界关系。

本文档的目标是稳定产品骨架，避免后续在页面设计和开发过程中不断出现职责重叠。

本文档不处理：

- 具体交互细节
- 页面布局草图
- 视觉样式细节
- 页面内按钮与状态规则

## 2. 首版一级能力区域

首版固定为以下 6 个信息架构一级能力区域：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

这里的“一级”指信息架构层级，不预设 UI 上一定占据一个独立导航按钮。

其中，“记一笔”虽然是一级能力，但它可以在后续 UI 设计阶段被实现为首页主入口、主操作按钮或其它顶层入口形式。

## 3. 页面划分总原则

页面划分应遵守以下原则：

- 首页负责情绪入口与轻概览，不负责深度管理
- 记录负责历史账目管理，不负责承担产品气质首页功能
- 记一笔负责高频录入，不承担复杂资产管理
- 资产负责账户与余额视角，不负责替代完整记录页
- Agent 负责协作陪伴，不负责替代记录页和首页
- 我的负责低频能力汇总，不承担主流程核心动作

## 4. 首页职责

### 4.1 首页负责什么

首页负责：

- 承担产品的第一视觉印象
- 提供陪伴感和连续使用感
- 提供轻量但有方向感的财务概览
- 提醒用户最近值得关注的内容
- 为高频动作提供自然导流

### 4.2 首页不负责什么

首页不负责：

- 完整历史账目浏览
- 深度统计分析
- 复杂筛选和搜索
- 全量资产管理明细
- 低频设置项承载

### 4.3 首页在产品中的角色

首页是“感受与方向”的页面。

它的核心不是告诉用户“所有数据”，而是告诉用户：

- 现在状态如何
- 最近值得注意什么
- 接下来可以去做什么

## 5. 记录页职责

### 5.1 记录页负责什么

记录页负责：

- 展示完整历史账目
- 提供按时间回顾的主要入口
- 提供查找、筛选、管理账目的能力
- 承担编辑记录、查看明细等操作延展

### 5.2 记录页不负责什么

记录页不负责：

- 承担产品主视觉首页
- 提供过强的资产总览角色
- 成为设置或偏好能力入口

### 5.3 记录页在产品中的角色

记录页是“账目运营页”。

它应该是用户在需要查清楚“到底发生了什么”时最可信赖的页面。

## 6. 记一笔职责

### 6.1 记一笔负责什么

记一笔负责：

- 提供最快速的交易录入路径
- 成为整个产品最直接的高频动作能力
- 降低从打开入口到完成记录之间的阻力

### 6.2 记一笔不负责什么

记一笔不负责：

- 展示大量历史记录
- 做完整资产配置管理
- 承担复杂设置与个性化配置

### 6.3 记一笔在产品中的角色

记一笔是“行动能力”。

它要体现的是低阻力和高确定性，而不是信息丰富度。

## 7. 资产页职责

### 7.1 资产页负责什么

资产页负责：

- 展示账户与余额相关状态
- 建立超越单笔账目的财务结构视角
- 承接资产相关能力的一级入口
- 让用户看到自己的财务秩序感

### 7.2 资产页不负责什么

资产页不负责：

- 替代完整记录页
- 成为图表统计中心
- 承担低频设置容器角色

### 7.3 资产页在产品中的角色

资产页是“结构页”。

如果说记录页讲的是“发生过什么”，资产页讲的是“我现在拥有什么、处于什么状态”。

## 8. Agent 页职责

### 8.1 Agent 页负责什么

Agent 页负责：

- 承接用户与助手的独立关系
- 提供财务提醒、总结、解释与建议
- 承接待确认记录、协作事项或其它 Agent 产出
- 成为产品中的主动陪伴层

### 8.2 Agent 页不负责什么

Agent 页不负责：

- 替代记录页的完整历史管理
- 替代首页的产品主氛围表达
- 替代“记一笔”的直接录入动作

### 8.3 Agent 页在产品中的角色

Agent 页是“协作页”。

它体现的是产品不只是一个静态工具，而是一个具备主动陪伴能力的财务助手。

## 9. 我的页职责

### 9.1 我的页负责什么

我的页负责：

- 承接低频能力
- 承接个人偏好与设置能力
- 汇总非主流程但必要的功能入口
- 作为产品的个人控制层

### 9.2 我的页不负责什么

我的页不负责：

- 承担核心记账动作
- 作为财务信息主展示页
- 代替首页的产品气质表达

### 9.3 我的页在产品中的角色

我的页是“收纳页”。

它承接次级能力，但不应抢占首页、记录页和资产页的主叙事位置。

## 10. 页面之间的关系

6 个一级能力区域之间应形成以下关系：

- 首页负责引导与情绪基调
- 记录负责追溯与管理
- 记一笔负责高频输入
- 资产负责状态与秩序
- Agent 负责协作与陪伴
- 我的负责收纳与偏好

它们之间不应互相侵占职责，否则会重新回到旧产品里“页面都在做一点，但都不够清晰”的状态。

## 11. 首页与记录页的边界

首页与记录页最容易发生职责混淆，因此单独定义：

首页回答：

- 最近怎样
- 现在状态如何
- 值得关注什么

记录页回答：

- 具体发生了什么
- 历史账目有哪些
- 我要如何查找和管理它们

简单说：

- 首页偏“感受 + 方向”
- 记录偏“事实 + 管理”

## 12. 记录页与资产页的边界

记录页与资产页的区别在于视角不同：

- 记录页看的是事件流
- 资产页看的是状态面

记录页应更关注“账目明细与时间序列”，资产页应更关注“账户结构与余额关系”。

## 13. Agent 与其它页面的边界

Agent 与其它页面的关系应明确如下：

- Agent 不替代首页的情绪入口角色
- Agent 不替代记录页的历史管理角色
- Agent 不替代“记一笔”的直接输入角色
- Agent 可以与上述页面协同，但不应吞并它们

也就是说：

- 首页负责“我现在怎样”
- 记录负责“到底发生了什么”
- 记一笔负责“我现在要记一笔”
- Agent 负责“我可以如何被协助”

## 14. 首页与我的页的边界

首页不应被各种低频入口挤满。

“我的”应承担：

- 主题
- 偏好
- 分类相关入口
- 低频管理能力

这样首页才能保持产品气质，而不退化成“什么都放一点”的首页。

## 15. 结论

首版 6 个信息架构一级能力区域已经具备清晰角色：

1. 首页：情绪入口与轻概览
2. 记录：历史账目管理
3. 记一笔：高频录入
4. 资产：账户与余额状态
5. Agent：协作与陪伴
6. 我的：低频能力收纳

后续无论做 UX、视觉还是代码重构，都应优先服从这一层页面职责划分。
