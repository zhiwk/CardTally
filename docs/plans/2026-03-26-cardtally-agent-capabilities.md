# CardTally Agent 专项能力文档

## 1. 文档目的

本文档用于定义 CardTally 首版中 Agent 的角色边界、能力范围和与基础产品的关系。

这份文档的目标不是把 Agent 描述成产品本体，而是明确：

- Agent 在首版中负责什么
- Agent 不负责什么
- Agent 如何与首页、记录、记一笔、资产、我的协作
- Agent 如何作为增强层存在，而不是依赖层

## 2. Agent 定位

CardTally 中的 Agent 定位为：

一个独立存在的财务助手角色，为用户提供协作、提醒、解释、建议和陪伴。

它不是：

- 唯一记账入口
- 唯一查询入口
- 基础产品缺陷的补丁
- 一个被藏在角落里的附属功能

它是：

- 一个独立能力区域
- 一个增强体验上限的角色
- 一个参与产品陪伴感建设的核心层

## 3. 核心原则

### 3.1 Agent 是增强层

没有 Agent，CardTally 也必须是一个完整、清晰、优秀的记账产品。

### 3.2 Agent 不替代基础主链路

用户必须始终可以：

- 不通过 Agent 直接记一笔
- 不通过 Agent 直接查看记录
- 不通过 Agent 直接查看资产
- 不通过 Agent 完成基础设置

### 3.3 Agent 负责提升体验上限

Agent 的价值不是“没有它就不能用”，而是“有了它之后更轻松、更聪明、更有陪伴感”。

## 4. 首版中 Agent 的职责

首版中，Agent 负责以下几类能力：

### 4.1 协作

Agent 可以协助用户理解和整理财务信息，例如：

- 帮助用户理解一段财务状态
- 针对用户问题提供解释
- 帮助用户更轻松地整理输入内容

### 4.2 提醒

Agent 可以承担轻量提醒角色，例如：

- 最近有值得关注的支出变化
- 某类财务状态值得查看
- 某项待处理事项需要确认

### 4.3 总结

Agent 可以提供面向用户的轻量总结，例如：

- 近期消费倾向
- 某段时间的简单回顾
- 与用户行为相关的总结性描述

### 4.4 建议

Agent 可以给出轻量建议，例如：

- 某笔记录可能适合哪个分类
- 某项记录信息可能需要补充
- 某项财务状态可能值得进一步查看

## 5. 首版中 Agent 不负责的内容

以下内容不应在首版中由 Agent 独占或强绑定：

- 唯一录入记录
- 唯一完成记账
- 唯一提供账目搜索
- 唯一解释财务状态
- 复杂自动化记账流水线
- 过深的多步审批式交互

换句话说，Agent 不能把基础产品变成“必须先和助手对话，才能完成正常使用”的产品。

## 6. Agent 与各一级能力区域的关系

### 6.1 Agent 与首页

首页负责：

- 情绪入口
- 轻量概览
- 产品第一印象

Agent 负责：

- 作为首页中的可被引导进入的协作角色
- 提供提醒、总结、陪伴延展

边界：

- 首页不能被 Agent 吞掉
- Agent 不能替代首页承担主视觉首页角色

### 6.2 Agent 与记录

记录负责：

- 历史账目浏览
- 搜索、筛选、管理
- 编辑与回顾

Agent 负责：

- 针对记录提供解释、建议、待确认内容

边界：

- 记录页是事实管理页
- Agent 是协作层，不替代管理页

### 6.3 Agent 与记一笔

记一笔负责：

- 最直接的录入动作
- 低阻力完成记录

Agent 负责：

- 在适当场景下辅助补全和建议

边界：

- 用户必须可以不通过 Agent 直接完成记账
- Agent 不能让“记一笔”从快捷动作退化成复杂对话流程

### 6.4 Agent 与资产

资产负责：

- 账户与余额状态
- 财务结构视角

Agent 负责：

- 帮助解释资产变化
- 提示值得关注的状态

边界：

- 资产页是结构页
- Agent 不替代资产页成为主要状态页

### 6.5 Agent 与我的

我的负责：

- 低频设置与偏好
- 个人控制层

Agent 负责：

- 提供与助手相关的独立能力空间

边界：

- Agent 不应被完全塞进“我的”
- 但 Agent 的权限、偏好、数据相关设置可以收纳在“我的”中

## 7. 首版建议纳入的 Agent 能力

首版建议纳入以下能力：

1. 独立 Agent 入口
2. 基础会话空间
3. 轻量财务提醒
4. 轻量财务总结
5. 对记录或财务状态的辅助解释

这几项能力已经足以让用户感知到 Agent 的价值，但不会破坏基础产品清晰度。

## 8. 首版可后置的 Agent 能力

以下能力可以保留为后续迭代方向，不应在首版强推：

- 高自动化记账
- 多来源自动解析
- 复杂待确认工作流
- 深层个性化记忆机制
- 面向大量复杂规则的主动代理能力

## 9. Agent 的成功标准

首版中的 Agent 是否成功，不取决于它“做了多少事”，而取决于以下几点：

- 用户能明显感知到它的存在价值
- 它确实降低了一部分理解和处理成本
- 它没有让基础产品变复杂
- 它没有吞掉首页、记录、记一笔的主职责

## 10. 结论

CardTally 首版中的 Agent，应作为一个独立、清晰、可感知的增强层存在。

它的任务是：

- 协作
- 提醒
- 总结
- 解释
- 建议

而不是替代基础记账软件本身成立。
