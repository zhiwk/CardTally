# CardTally 信息架构与导航落地规范（V1）

## 1. 文档目的

本文档将首版信息架构落地为可执行的导航规范，统一以下内容：

- 一级能力区域如何在 UI 中暴露
- 主导航与页面内功能入口的关系
- `记一笔` 的入口策略
- 跨页面跳转规则
- 与 Agent 相关的入口协作规则

本文档是首版导航行为的约束文件，后续 UX 与开发均以此为准。

## 2. 首版信息架构确认

首版信息架构一级能力区域固定为：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

说明：

- 这里的“一级”是信息架构概念，不等于每个都必须是底部导航 tab。
- `记一笔` 是一级能力，但不作为底部导航 tab，首版通过首页与记录页的 FAB 进入。

## 3. 主导航落地方案

首版采用“5-tab + 页面内 FAB 入口”模式：

- 底部导航 tab：`首页` / `记录` / `资产` / `Agent` / `我的`
- `记一笔`：通过首页与记录页的 FAB 进入，不做底部导航 tab

这样可同时满足：

- `记一笔` 保持一级能力地位
- 主导航保持克制和稳定
- 页面角色边界更清晰

## 4. 一级入口定义

### 4.1 首页入口

- 来源：底部导航 tab
- 角色：默认启动页

### 4.2 记录入口

- 来源：底部导航 tab
- 角色：历史账目管理主入口

### 4.3 记一笔入口

- 来源：首页 FAB、记录页 FAB
- 角色：高频录入主入口

约束：

- 首页与记录页的 FAB 是手动“记一笔”的唯一一级入口形式
- 不要求所有一级页面都提供“记一笔”入口

### 4.4 资产入口

- 来源：底部导航 tab
- 角色：账户与余额状态入口

### 4.5 Agent 入口

- 来源：底部导航 tab
- 次级入口：首页 Agent 卡片、记录页建议入口
- 角色：独立协作助手入口

### 4.6 我的入口

- 来源：底部导航 tab
- 角色：低频能力收纳入口

## 5. 页面栈与导航行为规则

### 5.1 一级页面切换规则

- 一级页面之间切换使用底部导航。
- 切换到其它一级页面时，回到该页最近一次稳定状态。

### 5.2 二级页面导航栏规则

- 进入二级页面时，底部导航栏收起。
- 从二级页面返回时，恢复到底部导航所在的一级页面。

### 5.3 `记一笔` 任务流规则

- 从首页或记录页点击“记一笔”进入任务流页面。
- 该流程作为独立任务页处理，不并入底部导航。
- 取消或完成后，返回触发来源页。

### 5.4 外部直达（深链）规则

说明：

- “深链”指从外部直接打开 App 内部页面（例如通知、分享链接、快捷指令）。

规则：

- 外部直达进入二级页面时，底部导航栏收起。
- 返回时，回到最近可用一级页（优先对应所属一级区域）。

## 6. `记一笔` 专项导航规范

`记一笔` 作为一级能力，但采用“页面内 FAB 入口 + 独立任务流”实现，需遵守：

- 首页必须有 FAB 形式的“记一笔”入口
- 记录页必须有 FAB 形式的“记一笔”入口
- 资产页不提供“记一笔”入口
- Agent 页不默认提供“记一笔”入口（后续如新增需另行评审）
- 我的页不提供“记一笔”入口

目标是保持“快、确定、低阻力”，同时维持页面边界清晰。

## 7. 资产页动作边界规范

资产页动作只处理资产域能力，不混入记账域高频动作：

- 资产页新增按钮仅用于“新增资产”
- 资产页不引导到“记一笔”
- 资产页如需补录账目，应通过返回首页/记录页后进入“记一笔”

## 8. Agent 相关导航规范

Agent 是独立一级区域，但不能吞并基础主链路：

- Agent 建议动作应优先引导到记录页或资产页对应能力
- Agent 不作为“记一笔”的默认主入口
- Agent 内触发写操作时，应标记来源为 Agent（用于审计）

## 9. 跨区域跳转矩阵（V1）

允许的一级到一级引导：

- 首页 -> 记录 / 资产 / Agent / 记一笔
- 记录 -> 记一笔 / Agent / 资产
- 资产 -> 记录 / Agent
- Agent -> 记录 / 资产
- 我的 -> Agent（可选）

不建议的跳转：

- 强制从 Agent 才能进入记账
- 资产页直接跳转“记一笔”
- 将首页所有主动作都重定向到 Agent

## 10. 导航一致性规范

首版必须保证以下一致性：

- 图标语义一致（同一能力只用同一图标语义）
- 一级入口命名一致（全局文案统一）
- 同一动作的反馈位置和样式一致
- 返回行为一致（避免同类路径返回不一致）

## 11. 可用性兜底规范

导航设计必须满足以下兜底要求：

- 单手可达：首页和记录页内的“记一笔”入口应易触达
- 路径最短：高频任务不超过 2-3 步进入
- 低认知负担：一级入口语义清晰
- 可恢复：中断后可回到稳定入口

## 12. 开发落地检查清单

开发前检查：

- 6 个一级能力区域是否都映射到可达入口
- 首页和记录页是否都具备“记一笔”入口
- 资产页新增动作是否限定为“新增资产”
- Agent 是否为独立入口且不替代主链路

开发后检查：

- 一级切换行为是否一致
- 二级页面是否都收起底部导航栏
- `记一笔` 从首页和记录页进入与返回是否符合规则
- 外部直达二级页时导航栏状态是否正确
- 无 Agent 场景下是否仍可完整完成核心流程

## 13. 结论

CardTally 首版导航采用“5-tab + 页面内记一笔 FAB 入口”：

- tab：`首页 / 记录 / 资产 / Agent / 我的`
- `记一笔`：仅由首页与记录页 FAB 进入

该方案同时满足信息架构完整性、交互效率和 Agent 增强层边界，是首版可执行的导航基线。
