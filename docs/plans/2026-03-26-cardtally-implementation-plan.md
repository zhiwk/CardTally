# CardTally 产品重开实施规划

## 1. 文档目的

本文档用于承接《CardTally 产品重开设计文档》，把已确认的产品方向转化为一个可执行的重构计划。

本文件仍然不展开具体 UX 细节，而是回答以下问题：

- 首版具体做哪些一级能力区域
- 旧项目的页面如何处理
- 重构顺序应如何安排
- 哪些内容应暂时延后

## 2. 实施目标

本轮重构的目标不是“在旧页面上继续优化”，而是建立一套新的产品骨架。

实施目标包括：

- 建立新的一级能力结构
- 为新产品建立新的视觉基础层
- 保留可复用业务能力，逐步替换旧页面呈现
- 引入独立 Agent 能力层
- 让首版先形成完整闭环，而不是功能堆砌

## 3. 首版范围

首版实现以下 6 个信息架构一级能力区域：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

这里的“一级”是信息架构概念，不等于它必须在 UI 上占用一个独立导航按钮。

其中，“记一笔”是一级能力，首版统一通过首页与记录页的 FAB 进入。

这 6 个一级能力区域构成首版主干闭环：

- 首页负责陪伴感与概览
- 记录负责历史账目管理
- 记一笔负责高频录入
- 资产负责财务状态
- Agent 负责协作、提醒、解释与建议
- 我的负责低频能力汇总

## 4. 旧页面处理原则

旧项目中的页面与能力，不应默认一比一保留。

处理原则如下：

- 能合并的不拆散保留
- 非首版核心能力先降级到“我的”或延后处理
- 与新定位冲突的旧结构不延续
- 可以复用逻辑，但不复用旧页面心智
- Agent 相关能力视为新增结构建设

## 5. 旧页面到新结构的映射建议

### 5.1 首页相关

旧页面：

- `HomeFragment`

处理建议：

- 不直接沿用旧首页结构
- 仅复用可复用的数据能力与部分列表展示逻辑
- 按全新首页思路重建

### 5.2 记录相关

旧页面：

- `HomeFragment` 中的记录列表能力
- `SearchFragment`
- `EditRecordFragment`
- 部分 `adapter`

处理建议：

- “记录”页作为完整历史账目页重建
- 搜索、筛选、编辑能力作为记录页的延展能力整合
- 不再让首页承担过重的账目管理角色

### 5.3 记一笔相关

旧页面：

- `AddRecordFragment`
- `EditRecordFragment`
- 快捷金额、分类选择等局部组件

处理建议：

- 将“记一笔”视为一级核心能力处理
- 录入体验按新产品重新定义
- 可复用旧录入逻辑，但 UI 与结构不保留

### 5.4 资产相关

旧页面：

- `AssetFragment`
- `AddAssetFragment`
- `EditAssetFragment`
- `AssetRecordsFragment`
- `ArchivedAssetsFragment`

处理建议：

- 资产页保留为一级能力区域
- 资产相关的新增、编辑、明细、归档能力先围绕一级资产页重新组织
- 首版优先建立“资产总览 + 关键入口”，细分流程后置

### 5.5 我的相关

旧页面：

- `SettingsFragment`
- `ThemeSettingsFragment`
- `CategoriesFragment`
- `CategoryManageFragment`
- 其它低频管理项

处理建议：

- 首版中统一归入“我的”
- “我的”不只是设置页，而是低频能力容器
- 旧设置结构不直接照搬，按新产品角色重新整理

### 5.6 Agent 相关

旧页面：

- 当前工程中暂无对应独立页面

处理建议：

- 作为新产品新增一级能力区域引入
- 首页、记录、记一笔、我的都可能与 Agent 发生连接
- 但 Agent 不替代这些区域本身的职责

### 5.7 统计页处理

旧页面：

- `StatisticsFragment`

处理建议：

- 不进入首版一级结构
- 首版暂不把统计作为独立一级区域
- 后续可选择并入首页延展模块、记录分析能力，或作为二级功能回归

## 6. 首版明确延后事项

以下内容不作为当前第一阶段重点：

- 独立统计一级页面
- 复杂数据可视化体系
- 全量设置能力重做
- 完整分类管理体验重做
- 过多主题定制能力
- 所有旧页面一次性同步升级
- 完整 Agent 工作流细化

延后这些内容的目的，是避免范围膨胀破坏新骨架的建立。

## 7. 推荐实施顺序

### 阶段一：定义新骨架

目标：

- 明确 6 个一级能力区域职责
- 确定主导航与主入口的结构关系
- 明确哪些旧能力进入首版，哪些延后

输出：

- 页面职责表
- 新旧页面映射表
- 首版范围冻结清单

### 阶段二：建立视觉基础层

目标：

- 建立新的颜色、间距、圆角、字体、表面层级基础
- 明确整体视觉语法

输出：

- 视觉基础规范
- 资源拆分方案
- 通用样式命名策略

### 阶段三：先做一级结构框架

目标：

- 先完成 6 个一级能力区域的结构骨架
- 形成新产品的整体观感

输出：

- 首页框架
- 记录页框架
- 记一笔框架
- 资产页框架
- Agent 页框架
- 我的页框架

### 阶段四：补主干闭环

目标：

- 让首版核心路径可走通
- 保证查看记录、记一笔、看资产、进入 Agent、进入个人页这些基本动作成立

输出：

- 首版可运行主路径
- 页面状态兜底
- 基础回归清单

### 阶段五：再补低频能力

目标：

- 将必要的低频能力逐步纳入“我的”或二级页面
- 对首版遗漏但必须存在的能力做有节制补齐

输出：

- 二级入口补充清单
- 后续迭代路线图

## 8. 实施中的判断标准

在执行过程中，所有页面设计和重构都应接受以下判断：

- 是否符合“静奢理财日记”的整体气质
- 是否强化了陪伴感，而不是工具后台感
- 是否保证高频动作仍然直接可达
- 是否有助于建立新产品主干，而不是修补旧结构
- 是否值得进入首版，而不是应该延后

如果某项内容不能通过以上判断，应优先考虑延后。

在本文件之后，建议继续补以下文档：

1. 页面职责文档

当前阶段不必把所有细节一次写完，但必须先确保结构与边界稳定。

## 10. 结论

CardTally 的首版重开应围绕新的 6 个信息架构一级能力区域展开，并以“先建骨架，再补细节”为核心策略推进。

具体来说：

1. 不延续旧页面组织方式
2. 复用旧逻辑，但重建页面结构
3. 将 Agent 作为新增独立能力区域引入
4. 暂缓统计页等非首版核心能力
5. 优先建立新产品观感、主干流程与视觉基础层

这样可以在控制范围的前提下，真正把项目带到一个新的起点上。
