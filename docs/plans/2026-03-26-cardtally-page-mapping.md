# CardTally 新旧页面映射文档

## 1. 文档目的

本文档用于把当前工程中的旧页面结构，映射到新的首版产品结构中。

它主要解决三个问题：

- 旧页面是否继续存在
- 旧页面应归入哪个新结构体系
- 旧页面对应能力在首版中如何取舍

本文档不定义具体交互，也不代表旧页面会被直接复用。它只负责建立迁移关系。

## 2. 新产品首版目标结构

首版新结构固定为以下 6 个信息架构一级能力区域：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

这里的“一级”指信息架构层级，不等于 UI 上一定要对应一个独立导航按钮。

## 3. 映射原则

映射时遵循以下原则：

- 优先映射“能力”，不是映射“旧页面外形”
- 旧页面可以被合并，不要求一一对应
- 非首版核心能力可以降级到“我的”或延后处理
- 与新产品定位冲突的旧页面结构不延续
- Agent 相关结构视为新增能力建设

## 4. 页面状态分类说明

为方便后续重构，旧页面统一按以下状态标记：

- `重建`：保留页面角色，但页面结构按新产品重做
- `并入`：不再作为独立一级或独立主页面存在，并入其它页面体系
- `收纳`：能力保留，但作为“我的”下的低频入口
- `延后`：能力可能保留，但不进入首版重点范围
- `新增`：旧工程中没有对应页面，新产品新增能力区域

## 5. 旧页面到新结构映射表

### 5.1 `HomeFragment`

旧职责：

- 首页
- 部分记录展示
- 部分概览职能

新结构归属：

- 对应新的“首页”

页面状态：

- `重建`

处理建议：

- 不保留旧首页布局与模块组织方式
- 只复用可复用的数据读取和展示能力
- 首页不再承担沉重的记录管理角色

### 5.2 `SearchFragment`

旧职责：

- 搜索账目
- 记录查找

新结构归属：

- 并入“记录”页体系

页面状态：

- `并入`

处理建议：

- 不再优先作为一级独立页面存在
- 后续作为记录页的扩展能力设计

### 5.3 `AddRecordFragment`

旧职责：

- 新增账目

新结构归属：

- 对应新的“记一笔”

页面状态：

- `重建`

处理建议：

- 录入逻辑可复用
- 页面结构、层级与视觉全部按新产品重做

### 5.4 `EditRecordFragment`

旧职责：

- 编辑账目

新结构归属：

- 归入“记录”页体系
- 与“记一笔”共享录入能力资产

页面状态：

- `并入`

处理建议：

- 不作为一级页面存在
- 首版中作为记录管理链路的延展能力存在

### 5.5 `StatisticsFragment`

旧职责：

- 统计分析
- 图表与汇总

新结构归属：

- 首版不进入一级结构

页面状态：

- `延后`

处理建议：

- 不作为首版一级页面保留
- 后续可拆解为首页延展、记录分析，或再次形成二级能力

### 5.6 `SettingsFragment`

旧职责：

- 设置
- 多种低频能力入口

新结构归属：

- 对应“我的”页面体系

页面状态：

- `重建`

处理建议：

- “我的”不是旧设置页平移
- 只保留其低频能力容器角色
- 页面叙事和结构按新产品重新定义

### 5.7 `ThemeSettingsFragment`

旧职责：

- 主题设置

新结构归属：

- 收纳至“我的”

页面状态：

- `收纳`

处理建议：

- 作为“我的”里的低频配置项
- 首版不单独强调其页面层级

### 5.8 `CategoriesFragment`

旧职责：

- 分类相关展示与入口

新结构归属：

- 收纳至“我的”

页面状态：

- `收纳`

处理建议：

- 首版不作为主导航页面
- 相关能力以后续二级入口方式保留

### 5.9 `CategoryManageFragment`

旧职责：

- 分类管理

新结构归属：

- 收纳至“我的”

页面状态：

- `收纳`

处理建议：

- 作为低频管理能力存在
- 首版不优先展开复杂体验重做

### 5.10 `AssetFragment`

旧职责：

- 资产总览

新结构归属：

- 对应新的“资产”

页面状态：

- `重建`

处理建议：

- 保留“资产是一级能力”的角色
- 页面结构按新产品整体气质彻底重建

### 5.11 `AddAssetFragment`

旧职责：

- 新增资产

新结构归属：

- 并入“资产”页体系

页面状态：

- `并入`

处理建议：

- 不作为一级主页面存在
- 后续作为资产页的功能延展

### 5.12 `EditAssetFragment`

旧职责：

- 编辑资产

新结构归属：

- 并入“资产”页体系

页面状态：

- `并入`

处理建议：

- 与资产新增、资产明细形成一组资产管理能力

### 5.13 `AssetRecordsFragment`

旧职责：

- 查看某资产相关记录

新结构归属：

- 同时连接“资产”与“记录”

页面状态：

- `并入`

处理建议：

- 首版中不必先做成独立重页面
- 后续可作为资产详情链路中的子能力

### 5.14 `ArchivedAssetsFragment`

旧职责：

- 已归档资产查看

新结构归属：

- 归入“资产”页体系的低频能力

页面状态：

- `收纳`

处理建议：

- 首版不优先强化
- 先作为低频资产管理能力保留

### 5.15 Agent 新增能力

旧职责：

- 当前工程中暂无独立 Agent 页面

新结构归属：

- 对应新的“Agent”

页面状态：

- `新增`

处理建议：

- 作为新产品新增一级能力区域引入
- 与首页、记录、记一笔形成协作关系
- 后续通过新增页面与能力定义补齐

## 6. 非页面层能力映射建议

除页面本身之外，当前工程里还有一些能力应以“组件或逻辑资产”方式迁移，而不是页面平移：

- 记录列表能力
- 分类选择能力
- 快捷金额能力
- 资产列表能力
- 主题切换能力
- 搜索能力

这些能力在新版本中应作为可复用模块重新组织，而不是继续绑定旧页面结构。

## 7. 首版重点保留能力

首版建议重点保留的能力有：

- 查看记录
- 新增记录
- 编辑记录
- 查看资产
- Agent 协作入口
- 基础资产管理入口
- 进入“我的”中的基础设置能力

## 8. 首版降级能力

首版可降级但不必消失的能力有：

- 分类管理
- 主题设置
- 归档资产
- 搜索的高级形态

这些能力可先通过“我的”或页面内次级入口承接。

## 9. 首版延后能力

首版明确延后的能力有：

- 独立统计页
- 重图表的数据可视化体系
- 复杂多层设置结构
- 全量旧页面同步翻新
- 完整 Agent 工作流细化

## 10. 结论

当前工程中的旧页面，不应被理解为新产品的页面蓝图，而应被拆解为：

- 可复用的业务能力
- 可迁移的交互资产
- 需要重建的页面角色

首版真正保留为信息架构一级能力区域的，只有以下 6 个新角色：

1. 首页
2. 记录
3. 记一笔
4. 资产
5. Agent
6. 我的

其它旧页面一律按“并入、收纳、延后”处理。
