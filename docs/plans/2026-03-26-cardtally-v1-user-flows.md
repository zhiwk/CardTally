# CardTally 首版核心用户流程文档（V1）

## 1. 文档目的

本文档定义 CardTally 首版核心用户流程，确保以下目标同时成立：

- 基础记账产品可独立运行
- Agent 可独立完成全能力操作
- 导航行为与 IA 规范一致
- 资产与记录管理能力闭环完整

本文档面向产品、设计、开发共同使用，不展开页面视觉细节。

## 2. 全局流程原则

首版所有流程遵守以下原则：

- 手动路径和 Agent 路径都可完整完成核心任务
- Agent 不依赖人工补操作即可完成能力闭环
- 高风险写操作可追踪来源
- 二级页面进入后收起底部导航
- 返回行为优先回到触发来源页
- `记一笔` 入口只在首页和记录页提供

## 3. 流程清单（V1）

首版核心流程包含：

1. 手动记一笔（首页入口）
2. 手动记一笔（记录页入口）
3. 浏览与管理记录
4. 改一笔（编辑记录）
5. 删除记录
6. 查看资产
7. 新增资产
8. 修改资产
9. 归档资产
10. 恢复归档资产
11. 删除资产
12. Agent 全能力执行流程

## 4. 手动记一笔（首页入口）

### 4.1 目标

用户从首页快速录入一条新记录。

### 4.2 主路径

1. 用户进入首页
2. 点击首页“记一笔”按钮
3. 进入“记一笔”任务页（底部导航收起）
4. 输入金额、分类、时间、备注等必要信息
5. 点击保存
6. 系统创建记录并反馈结果
7. 返回首页

### 4.3 异常路径

- 输入不完整：阻止提交并提示缺失字段
- 保存失败：保留已填信息，提示重试
- 用户取消：不写入数据，返回首页

## 5. 手动记一笔（记录页入口）

### 5.1 目标

用户在查看历史账目时补录新记录。

### 5.2 主路径

1. 用户进入记录页
2. 点击记录页“记一笔”按钮
3. 进入“记一笔”任务页（底部导航收起）
4. 完成录入并保存
5. 返回记录页并可见新增结果

### 5.3 异常路径

- 取消录入：返回记录页，不产生写入
- 保存失败：保留输入并允许重试

## 6. 浏览与管理记录

### 6.1 目标

用户查看、定位、管理历史账目。

### 6.2 主路径

1. 用户进入记录页
2. 浏览记录列表
3. 使用搜索或筛选定位目标记录
4. 打开记录详情或直接进行操作

## 7. 改一笔（编辑记录）

### 7.1 目标

用户修正已有记录。

### 7.2 主路径

1. 用户在记录页定位到目标记录
2. 进入编辑流程（底部导航收起）
3. 修改金额、分类、时间、备注等字段
4. 保存修改
5. 返回记录页并显示更新结果

### 7.3 边界定义

- “改一笔”属于记录管理链路，不是一级独立入口
- 可以与“记一笔”共享编辑能力，但不共享入口角色

## 8. 删除记录

### 8.1 目标

用户删除错误或无效记录。

### 8.2 主路径

1. 用户在记录页定位目标记录
2. 点击删除操作
3. 系统进行二次确认
4. 用户确认删除
5. 系统删除成功并刷新列表

### 8.3 异常路径

- 用户取消确认：不删除，返回原状态
- 删除失败：提示失败并保留记录

## 9. 查看资产

### 9.1 目标

用户查看资产总览与资产明细状态。

### 9.2 主路径

1. 用户进入资产页
2. 浏览账户、余额、状态信息
3. 按需进入资产详情

### 9.3 边界定义

- 资产页不提供“记一笔”入口
- 资产页仅承载资产域能力

## 10. 新增资产

### 10.1 目标

用户新增一个资产账户或资产项。

### 10.2 主路径

1. 用户在资产页点击“新增资产”
2. 进入新增资产流程（底部导航收起）
3. 输入资产信息并保存
4. 返回资产页并刷新结果

## 11. 修改资产

### 11.1 目标

用户更新资产信息。

### 11.2 主路径

1. 用户在资产页进入目标资产详情
2. 点击编辑资产
3. 修改资产信息并保存
4. 返回资产页或资产详情并显示更新结果

## 12. 归档资产

### 12.1 目标

用户将不再活跃的资产转入归档状态。

### 12.2 主路径

1. 用户进入目标资产详情
2. 点击归档资产
3. 系统二次确认
4. 用户确认归档
5. 资产状态更新为归档

## 13. 恢复归档资产

### 13.1 目标

用户将已归档资产恢复为活跃状态。

### 13.2 主路径

1. 用户进入归档资产列表或归档资产详情
2. 点击恢复资产
3. 系统更新状态为活跃
4. 返回资产页并可见恢复结果

## 14. 删除资产

### 14.1 目标

用户删除不再需要保留的资产。

### 14.2 主路径

1. 用户进入目标资产详情
2. 点击删除资产
3. 系统二次确认
4. 用户确认删除
5. 系统删除成功并刷新资产列表

### 14.3 异常路径

- 用户取消确认：不删除，返回原状态
- 删除失败：提示失败并保留资产

## 15. Agent 全能力执行流程

### 15.1 目标

Agent 在用户授权范围内可独立完成所有核心能力。

### 15.2 覆盖能力

Agent 可执行：

- 创建记录
- 修改记录
- 删除记录
- 查询记录
- 新增资产
- 修改资产
- 归档资产
- 恢复归档资产
- 删除资产
- 查询资产

### 15.3 主路径

1. 用户进入 Agent 页并下达任务
2. Agent 解析任务并匹配对应能力
3. Agent 直接执行能力调用
4. 系统返回执行结果
5. Agent 向用户反馈结果与关键变更

### 15.4 关键约束

- Agent 路径不要求人工补操作才能闭环
- 所有写操作必须可追踪来源与结果
- 对高风险操作保留确认策略

## 16. 流程状态与结果反馈规范

首版关键流程应统一反馈模型：

- 成功：明确成功提示 + 返回来源页
- 失败：错误提示 + 保留可恢复输入
- 取消：不写入，返回来源页
- 待确认（可选）：标注状态并可继续处理

## 17. 事件追踪与审计要求

与流程相关的关键事件应可记录来源：

- 来源页（首页/记录/资产/Agent）
- 操作类型（创建/编辑/删除/查询/归档/恢复）
- 触发方式（用户手动/Agent 直接执行）
- 结果状态（成功/失败/取消）

## 18. 验收清单（V1）

验收时至少确认：

1. 记录支持新增、编辑、删除闭环
2. 资产支持新增、修改、归档、恢复、删除闭环
3. “记一笔”只在首页和记录页可进入
4. 资产页新增动作只用于新增资产
5. 二级页面进入后底部导航收起
6. Agent 可独立完成核心能力操作

## 19. 结论

CardTally 首版流程基线是：

- 手动流程完整闭环
- 资产与记录管理能力完整闭环
- Agent 路径可独立完成全能力
- 导航与流程边界一致

这套流程可直接作为下一阶段 UX 细化和开发拆分的执行依据。
